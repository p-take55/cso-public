# ミッション・ビジョン・経営方針と現状（①ミッション・ビジョン、②事業環境分析）

先に `cso-records` を読み、記録の形と版の規則に従う。

## 初回の相談

1. 目次 `docs/cso-index/current.md` を探す。なければ作る（`settings.business`・`owner`・`unit` を利用者に合わせる。`current` は空）。
2. 最初に聞くのは1つだけ：「いま一番決めたいことは何ですか。それを決めるために、手元にある数字を見せてください」。6業務を順番に進めることを求めない。
3. 受け取った材料ごとに `cso-source/src-….md` を作る（種類・期間・受け取った日・使った項目・読めなかった部分）。
4. 月別の数字を取り出し、`cso-analysis` の `series` に入れる。行（国内・海外、店内・テイクアウトなど）は利用者の事業に合わせて決める。材料にない月は `null`。
5. 本人が何かを変えた期間（ページを増やした、営業時間を変えたなど）を会話から拾い、`annotations` に書く。数字の動きとの関係は断定せず、「この数字だけでは分からない」ことを `note` に書く。
6. 「分かっていること」（`facts`）と「まだ分からないこと」（`unknowns`）に分ける。
7. 市場・競合は、この回で調べられなければ `unknown` にする。架空の出典を付けない。
8. 利用者に頼む作業は1つだけにする（例：国別の明細）。
9. 版idを `next-id` で決め、`status: final` で保存し、目次の `current.analysis` を更新して `build` する。

## 2回目以降

- **顧客の声**：問い合わせ・口コミ・予約時のメモなどを読み、内容で分類して件数を数える（`voices`）。個人名・連絡先は写さない。
- **過去の試みの読み直し**：うまくいかなかった試み（例：卸のメール）を読み直し、何が分かったのに記録されていなかったかを `facts` に書く。
- **市場と競合**：Webで公開情報を調べられる場合は調べ、項目ごとに出典（URL）と調べた日付を台帳に残す。調べられない場合は `unknown`。
- **手持ちの力**（`strengths`）：経歴・取引先・顧客・設備など、すでに持っているものを書く。次の戦略で候補を作る材料になる。

## ミッション・ビジョン・経営方針

記録の `cso-direction` に書く。見出しと中身は次のとおり。

| 見出し | 書くこと | データ |
|---|---|---|
| ミッション | 誰に、どんな価値を届けるか（1文） | `purpose` |
| ビジョン | 将来どういう事業にしたいか。年月と、数で確かめられる項目 | `vision`（`horizon`・`items`） |
| 経営方針 | 何を重視して、事業を進めるか | `donts` |
| 本人が行うこと | 値段の変更・外部への送信・支払い・公開など、利用者が自分で行うと決めたこと | `owner_hands` |

- 会話の中で利用者が自分で言ったことから下書きする。CSOが考えた文言には `mark: "guess"` と `reason: "CSOの案"` を付ける。
- 経営方針は、戦略と計画を選ぶときの判断の方針として書く。「〜しない」と言われたら、何を選ぶかの文にする（例：「人を雇わない」→「増員せずに運営できる事業を選ぶ」）。利用者が決めた条件・数値・期限は変えず、緩めず、言われていない目標（利益目標など）を足さない。理由を言っていればかっこで添える。期限があるものは `values.until`。
- 拡大を目指す人もいれば、目指さない人もいる。どちらかを勧めない。
- 「AIに任せない」「自分の手でやる」のようなCSOの権限に関わることは、経営方針に入れず `owner_hands` に書く。
- 利用者が直したら、直した文言で確定する。

## 版を変えるとき

ミッション・ビジョン・経営方針や現状を変えるときは新しい版を作る（`supersedes` と `changed_by`）。古い版は書き換えない。

文言だけを直すときも新しい版にする。本文に「文言の修正（条件・数値・期限は前の版と同じ）」と書き、`changed_by` に直すと決めた会話の材料id（`src-conv-…`）を入れる。項目のidは変えない。
